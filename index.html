Project Architecture

TCS BaNCS — Trade Finance Modernization

In my current project at TCS BaNCS, the original application is built on a Struts framework and follows a monolithic layered architecture. Most of the trade finance functionality was developed in Struts, so the presentation layer, business layer, and database layer are tightly coupled.

From the last financial year, our organization started a modernization initiative to migrate selected trade finance modules to Spring Boot microservices, and I have been involved in that migration. We are following the Strangler Fig Pattern, which means we are not rewriting the entire monolithic application at once. Instead, we are gradually replacing individual modules with Spring Boot microservices. Because of this, both the legacy Struts application and the new microservices currently coexist, which allows us to modernize the application without affecting existing banking operations.

The new architecture starts with a React-based frontend. When a user performs an operation, such as creating or updating a Letter of Credit, the request first goes to an API Gateway. The API Gateway handles routing, authentication, authorization, and logging. We use Spring Security with JWT, so the gateway validates the token and the user's permissions before forwarding the request to the appropriate microservice.

Inside each microservice, we follow a layered architecture with Controller, Service, Repository, and Database layers. The Service layer contains the business logic, and the Repository layer interacts with Oracle or PostgreSQL using Spring Data JPA and Hibernate.

For audit logging, notifications, document generation, and reporting, we use Kafka. After the main transaction is completed, the service publishes an event to Kafka, and separate consumer services process those tasks asynchronously. This reduces response time and allows services to scale independently.

For monitoring and debugging, we use OpenTelemetry for distributed tracing. A Trace ID is generated and propagated across all microservices, which helps us trace a request end-to-end and quickly identify production issues.

For deployment, each microservice is packaged using Docker and deployed through Jenkins CI/CD pipelines. Since each service is independently deployable, we can release one module without impacting the others.

Overall, our architecture is a hybrid of the legacy Struts monolith and Spring Boot microservices, and using the Strangler Fig Pattern has allowed us to gradually modernize the application while maintaining the stability required for a banking product like TCS BaNCS.
